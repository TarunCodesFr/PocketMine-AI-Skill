# Config System Guide

Every plugin generated by this skill ships with two components: a `config.yml` and a `PluginConfig.php`. This document explains the pattern and how to extend it.

---

## Why This Pattern Exists

Most PocketMine plugins have this scattered across their code:
```php
$plugin->getConfig()->get('combat-duration', 15);
$plugin->getConfig()->getNested('messages.no-permission');
```

This is bad for three reasons:
1. **No type safety** — `get()` returns `mixed`; callers need to cast manually
2. **No discoverability** — can't tell which config keys exist without reading the YAML
3. **No centralization** — changing a key name requires a grep across the entire codebase

The `PluginConfig` pattern solves all three.

---

## The Pattern

```
config.yml          ← Source of truth; human-readable; every key has a comment
PluginConfig.php    ← Type-safe wrapper; one getter per key; single point of access
```

**Rule:** No class other than `PluginConfig.php` ever calls `getConfig()`.

## config.yml Structure

### Required Sections (All Plugins)

```yaml
# =============================================================
# PluginName Configuration  vX.Y.Z
# =============================================================

# ---- General -------------------------------------------------
prefix: "&7[&bPluginName&7] &r"
debug: false

# ---- Messages ------------------------------------------------
messages:
  no-permission: "{prefix}&cYou don't have permission."
  player-only:   "{prefix}&cIn-game only."
  reload:        "{prefix}&aConfig reloaded."
  usage:         "{prefix}&cUsage: &e{usage}"

# ---- Database ------------------------------------------------
database:
  type: yaml   # yaml | mysql
  mysql:
    host: "127.0.0.1"
    port: 3306
    user: "root"
    password: ""
    database: "minecraft"

# ---- Permissions Overview ------------------------------------
# plugin.command         → All players
# plugin.command.admin   → OPs only
```

### Feature-Specific Sections

Add sections below the required ones. Each section must:
- Have a `# ----` header comment
- Have a comment on every key explaining what it does
- Include example values or valid options in comments

## PluginConfig.php Structure

```php
final class PluginConfig {

    public function __construct(private readonly Main $plugin) {}

    // ── Reload ───────────────────────────────────────────────
    public function reload(): void {
        $this->plugin->reloadConfig();
    }

    // ── General ──────────────────────────────────────────────
    public function getPrefix(): string {
        return TextFormat::colorize(
            (string) $this->plugin->getConfig()->get('prefix', '&7[&bPlugin&7] &r')
        );
    }

    public function isDebug(): bool {
        return (bool) $this->plugin->getConfig()->get('debug', false);
    }

    // ── Messages ─────────────────────────────────────────────
    public function getMessage(string $key, array $placeholders = []): string {
        $raw = (string) $this->plugin->getConfig()->getNested("messages.$key", "&cMissing: $key");
        $msg = str_replace('{prefix}', $this->getPrefix(), $raw);
        foreach ($placeholders as $ph => $value) {
            $msg = str_replace('{' . $ph . '}', $value, $msg);
        }
        return TextFormat::colorize($msg);
    }

    // ── Database ─────────────────────────────────────────────
    public function getDatabaseType(): string { ... }
    public function getMysqlHost(): string { ... }
    // ... etc.

    // ── Feature: Cooldowns ───────────────────────────────────
    public function getDefaultCooldown(): int {
        return max(0, (int) $this->plugin->getConfig()->getNested('cooldowns.default', 30));
    }

    public function isVipBypassCooldown(): bool {
        return (bool) $this->plugin->getConfig()->getNested('cooldowns.vip-bypass', true);
    }

    // ── Debug helper ─────────────────────────────────────────
    public function debug(string $message): void {
        if ($this->isDebug()) {
            $this->plugin->getLogger()->debug("[DEBUG] $message");
        }
    }
}
```

## Adding a New Config Key

1. **Add to `config.yml`** with a comment:
   ```yaml
   # Maximum number of players per arena. Minimum: 2.
   max-players: 16
   ```

2. **Add a getter to `PluginConfig.php`**:
   ```php
   public function getMaxPlayersPerArena(): int {
       return max(2, (int) $this->plugin->getConfig()->getNested('max-players', 16));
   }
   ```

3. **Use the getter** in your code:
   ```php
   if (count($this->players) >= $this->config->getMaxPlayersPerArena()) {
       $player->sendMessage($this->config->getMessage('arena-full'));
   }
   ```

## The Reload Command Pattern

Every plugin should support `/pluginname reload`:

```php
// In the command class
private function handleReload(CommandSender $sender): void {
    if (!$sender->hasPermission('pluginname.command.admin')) {
        $sender->sendMessage($this->config->getMessage('no-permission'));
        return;
    }
    $this->config->reload();
    $sender->sendMessage($this->config->getMessage('reload'));
}
```

The `PluginConfig::reload()` method calls `$plugin->reloadConfig()` which re-reads the YAML from disk. No restart needed.

## Placeholder System

The `getMessage()` method supports `{key}` placeholders:

```yaml
# config.yml
messages:
  economy-paid: "{prefix}&aYou paid &e${amount} &ato &b{player}&a."
  economy-received: "{prefix}&aYou received &e${amount} &afrom &b{player}&a."
```

```php
// Usage
$sender->sendMessage($this->config->getMessage('economy-paid', [
    'amount' => EconomyManager::format($amount),
    'player' => $receiver->getName(),
]));
```

Built-in placeholders always available: `{prefix}`.
